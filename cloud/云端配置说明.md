# 行政工作台：云端同步与 DeepSeek 公文起草

这份说明只适用于 admin-workbench。仓库公开：真实工作备份、Supabase 私钥、DeepSeek API 密钥不要提交到 GitHub，也不要发在聊天里。

你不需要先购买服务器或域名：现有 GitHub Pages 地址负责打开页面，Supabase 项目负责登录、云端存储和两端消息。免费项目适合先用虚构数据试运行，但长期不活跃可能被暂停；若以后要求持续在线，再评估 Supabase 付费方案。购买域名只改变网址，不会让同步自动变可靠。

## 1. 先备份

在正在使用的设备打开工作台 →「导入与导出」→「下载完整迁移包 ZIP」。新的 backup.json 包含四类原有台账、例文库和采购需求／报价／审批／验收记录。「已保存到本机」只代表这台设备存好了；「已同步 · 云端版本 N」才代表云端确认。

## 2. 创建 Supabase 项目

1. 到 https://supabase.com/ 注册并创建一个项目；选择合适地区。数据库密码只保存在自己手中，不输入网页。
2. 在项目后台打开 SQL Editor，新建查询，复制本仓库 cloud/schema.sql 的全部内容并运行。它创建用户私有的工作台表、带版本检查的保存函数和实时变更订阅。
3. 在 Authentication → URL Configuration，把 Site URL 和 Redirect URL 都配置为 https://ranran1001.github.io/admin-workbench/ 。保持邮箱登录可用。
4. 在项目 API Keys 页面找到 Project URL 与 publishable key（或旧版 anon key）；不要复制 secret 或 service_role key。
5. 打开行政工作台 →「多设备同步」，填写项目网址、公开密钥、自己的邮箱，先保存地址，再发送登录链接。在同一浏览器点邮件链接，返回工作台。
6. 首次连接先核对本机、云端记录数量。第一台设备通常选择「以本机数据建立云端副本」，等状态出现「已同步 · 云端版本 1」。第二台设备以同一邮箱登录，先备份本机，再点击始终可见的「检查并下载云端数据」；确认后才会替换这台设备的本机记录。如果第二台已显示「已同步」，它已经取到云端数据，无须再下载。
7. 建立自己的账号后，可到 Authentication 设置关闭 Allow new users to sign up；已有账号仍能登录。

## 3. 核对实时同步

两台设备登录同一邮箱，用虚构事项测试：电脑新增待办，等显示「已同步」，手机打开的页面会收到云端变化；手机切回前台时也会检查。断网时，本机保存后显示待同步，联网自动重试。若两端先后各自离线改动，会暂停上传并提示冲突；双方先备份，再人工选择保留版本。当前以整个工作台为同步单元，即使改动了不同事项也可能需要人工选版本。

采购比价模块随其他记录一起同步。原来已经运行过 `cloud/schema.sql` 的项目无需为了采购模块重新运行；现有保存函数允许在已有台账之外存储采购数据。旧云端记录缺少采购列表时会按空列表载入；请先在第一台设备完成备份，再确认另一个设备拿到最新版本。已在用的浏览器不会自动混入虚构采购示例。采购中的长篇截图或附件不要直接放进同步数据，保存凭证的位置或链接即可；当前云端保存函数限制每次整份数据约 2 MB。

手机上若没看到云端数据，先看「多设备同步」中的登录状态：若写着「未登录」，邮件链接可能在微信、邮箱应用的内置浏览器里打开了，而工作台在另一个浏览器；请在**同一个浏览器**打开工作台和邮件链接。若已登录却显示「云端为空」，返回第一台设备确认同一项目网址、同一邮箱，并等到「已同步」。若显示读取失败，检查 SQL 是否已运行、网络是否可用。

手机写完就立刻划掉浏览器时，本机数据通常仍在，但云端上传可能被中断；下次打开会继续尝试。因此，请等看到「已同步」再切换设备。无痕模式、手动清理浏览器网站数据、设备损坏会影响本机副本；已确认上传到云端的版本可以从另一台登录设备取回。任何云服务也可能出现中断，所以保留定期备份。

手机语音输入后，文字先暂存在「随手记事」的本机输入框；务必再点「整理成待办」、核对日期、点「加入工作队列」。只有这时它才进入跨设备同步。输入框草稿不会自动跑到电脑上。

## 4. 连接 DeepSeek

1. 在 https://platform.deepseek.com/ 注册、了解 API 计费，并创建 API Key。以平台显示的账单为准。
2. 到 Supabase 的 Edge Functions → Secrets，新建 DEEPSEEK_API_KEY（填 DeepSeek API Key）和 ALLOWED_EMAIL（填登录工作台的邮箱）。
3. 在 Edge Functions 创建名为 draft-document 的函数，把 cloud/draft-document.ts 全文粘贴并部署。若使用新的 publishable key，关闭函数网关的旧版 Verify JWT；函数代码仍会验证用户身份，并只允许 ALLOWED_EMAIL 调用。
4. 打开工作台「公文起草」，用虚构内容填写主题与要点，选择「深度思考」或「快速起草」，先整理起草要求并核对，再点击「用 DeepSeek 起草」。深度思考可能等待更久且消耗更多输出额度。只有主动点击时，提示词及选中的例文才会发送给 DeepSeek。

## 5. 保存例文

在「公文起草」下方输入名称、类别和正文后保存。起草时在「参考例文」选中，就能作为结构与语气参考调用；例文保存在本机，也包含在 JSON／ZIP 备份里。接通云端后随其他数据同步。先去掉不宜发送给第三方模型的内容。

## 状态说明

| 显示 | 含义 |
| --- | --- |
| 已保存到本机／仅本机保存 | 另一台设备未必能看到。 |
| 本机已保存 · 正在上传 | 云端尚未确认，先不要关闭网页。 |
| 已同步 · 云端版本 N | 云端已确认，另一台在线设备可接收变化。 |
| 本机已保存 · 离线待同步／云端失败 | 数据仍在本机，网络恢复后会重试。 |
| 检测到两端修改 | 上传暂停；下载双方备份后选版本。 |

云端同步依赖网络和服务状态，仍应定期下载备份。网页关闭后浏览器不会自行检查到期；日历文件需手动导入设备日历。
